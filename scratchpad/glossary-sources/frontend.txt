## Frame: Frontend Development — Senior-Level Best Practices

- Component architecture: favor composition over inheritance — build small, focused components and assemble them via props/children rather than base-class hierarchies.
- Container/Presentational split: separate data-fetching and state logic (containers/hooks) from pure rendering (presenters); presenters take only explicit props and have no side effects.
- Extract a component when: markup repeats, a chunk grows a distinct responsibility, or you need to test/reuse it in isolation — not preemptively "for later."
- State management: keep state as local as possible; lift it only when sibling components actually need to share it.
  - Reach for Context for a few components needing read-mostly shared state (theme, auth) — Context is not a performance-free global store.
  - Reach for Redux/Zustand when you have complex cross-cutting state, need time-travel/devtools, or many unrelated components mutate the same data.
  - Prefer composition (pass components as children/slots) over a global store as the first fix for prop drilling.
- Rendering strategy tradeoffs: CSR (best for highly interactive apps, worse SEO/first paint), SSR (fresh data per request, higher server cost), SSG (fastest, stale until rebuild), ISR (SSG + background revalidation — best of both for
content that changes occasionally).
- Next.js App Router: Server Components by default (data fetching, secrets, zero client JS shipped); add 'use client' only for interactivity/hooks/browser APIs, and push client boundaries as deep (leaf) as possible.
- Streaming: wrap slow data-fetching components in Suspense boundaries so the page shell renders immediately instead of blocking on the slowest request.
- Performance — code splitting: use dynamic import()/next/dynamic for below-the-fold or rarely-used heavy components (charts, rich-text editors, modals).
- Memoization pitfalls: useMemo/useCallback/React.memo add real overhead and complexity — apply them only after profiling shows an actual re-render cost, not defensively everywhere.
- Core Web Vitals: optimize LCP (priority-load the hero image/text), CLS (reserve space for images/ads/fonts to avoid layout shift), and INP (keep the main thread free, break up long tasks).
- Bundle-size discipline: audit with a bundle analyzer, avoid pulling in heavy dependencies for small utilities, rely on tree-shaking, and prefer native platform APIs where reasonable.
- Accessibility: reach for semantic HTML first (button, nav, header, main) before ARIA; use ARIA only to fill gaps native elements cannot express.
- Keyboard navigation and focus management: every interactive element must be reachable and operable via keyboard; manage focus explicitly on route change, modal open/close, and dynamic content updates.
- Testing: unit test pure logic and hooks; use component tests (React Testing Library) for user-facing behavior and interaction rather than implementation details; reserve e2e (Playwright/Cypress) for a small set of high-value critical happy-
path flows.
- TypeScript discipline: never reach for `any` as an escape hatch — use `unknown` plus narrowing; model variants with discriminated unions instead of optional-flag soup; use generics for reusable components (e.g., a generic `List<T>`) to
preserve type safety across call sites.
- Interview archetypes to be ready to reason through: autocomplete (debounce input, cancel in-flight requests, keyboard nav, ARIA combobox pattern), virtualized list (windowing, fixed vs. variable row height), infinite scroll
(IntersectionObserver, cursor-based pagination, avoiding layout jump on load).

## Frame: Frontend Development — Community Resources & Further Reading

- React official docs — react.dev (Learn + Reference, especially "Thinking in React" and the Server Components guidance).
- Next.js official docs — nextjs.org/docs (App Router, Rendering, and Data Fetching sections).
- web.dev — Core Web Vitals and performance guidance maintained by the Chrome team.
- roadmap.sh/frontend — community-maintained frontend developer roadmap.
- "Refactoring UI" by Adam Wathan & Steve Schoger — practical, developer-focused UI design decisions.
- Kent C. Dodds — Testing JavaScript / Epic React (testing-library philosophy: "test behavior, not implementation").
- Josh W. Comeau's blog (joshwcomeau.com) — deep, visual explanations of CSS, React rendering, and animation.
- Patterns.dev — modern rendering patterns (SSR/SSG/ISR/streaming) and React design patterns.
- MDN Web Docs — canonical reference for HTML, CSS, ARIA, and Web APIs.
- WAI-ARIA Authoring Practices Guide (APG) — w3.org/WAI/ARIA/apg — canonical accessibility patterns (combobox, dialog, listbox, etc.).
